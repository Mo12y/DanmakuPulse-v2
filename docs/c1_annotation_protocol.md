# C1 互动节奏阶段标注协议 v1.0（冻结稿）

> **冻结时间**：2026-10-28 08:50（在生成任何 C1 算法分段输出之前）
> **适用范围**：C1 弹幕互动节奏阶段识别与分段（Gate A 人工一致性 → Gate B 算法有效性）
> **配套材料**：`data-out/c1/{sample30.csv, curves.csv, ann_A.csv, ann_B.csv, manifest.json}`
> **本协议一经冻结，修改必须升版本号并在 §11 变更记录中写明原因与受影响样本；受影响样本必须重标。**

## 0. 诚实披露（先于一切规则）

1. 本协议由项目作者（学生本人）起草。作者**此前看过** exp44/exp45 算法在 5–6 支视频上的输出与评估结果。
   为降低"按算法结果倒推标注规则"的风险，采取三条措施：
   - 规则来源锚定在**既有文件**：`docs/annotation_guides.md` v0 的高能片段标注纪律、exp43 的边界一致率口径、
     以及文献综述（Kleinberg 突发检测、孔玲玲/高旭 的弹幕高潮段、众包直播节奏），不引用任何 exp44/45 的阈值；
   - 协议中**不出现任何具体数值阈值**（如"2σ""+2√(λ+1)"），只给操作性定义；
   - 标注执行人（两位）在标注期间**不得查看任何算法分段输出**，材料包 `ann_*.csv` 与 `curves.csv`
     里不含算法结果列。
2. 在两位标注者完成前，**不得**把任何一致性数字写进报告（与 annotation_guides v0 的纪律一致）。
3. 标注者身份披露：第一标注者为项目作者本人，第二标注者为一名未参与算法实现的同学。
   项目作者不是中立第三方，这一利益冲突**随结果一并披露**。

## 1. 标注对象与粒度

- 对象：`sample30.csv` 里的 30 支视频（B 站单 P、`danmaku_got < 600`、时长 ≥ 300s、≥ 5 个分钟桶）。
- 粒度：**分钟桶**。所有阶段边界必须落在分钟边界上（`start_bucket` / `end_bucket` 为 0 起始的桶序号，
  `end_bucket` 为**闭区间**的最后一个桶）。
- 依据：数据粒度是 60s（`dws_rhythm_60s`），更细的边界无法用 60s 容差评估，也无法从曲线材料读出。

## 2. 什么是"一个互动节奏阶段"

连续的分钟桶区间 `[start_bucket, end_bucket]`，满足：
1. 区间内部强度形态**同质**（持续低、持续高、持续爬升、持续回落之一）；
2. 与**相邻区间**的强度水平或形态**可区分**（看曲线能说出"这里变了"）；
3. 区间内不含**未解释的采集缺失**（若有，按 §5.X 拆分或标记 X 类）。

一段视频整体只有一种形态时，允许标注为**单一阶段**（整段一段）；这不是偷懒，是定义的忠实执行。

## 3. 阶段类别（六值，闭集）

| 代码 | 名称 | 操作性定义 | 判据（看曲线） |
|---|---|---|---|
| `L` | 低活动铺底 | 计数长期接近 0，无持续强度 | 大段空白/贴地，偶发 1–2 条不算 |
| `R` | 上升/爬升 | 强度在一个可感知的尺度上逐级走高（≥2 级） | 台阶式上抬，不是单桶尖峰 |
| `H` | 持续高活动 | 强度持续高于该视频典型水平并维持 ≥3 桶 | "平台"，允许小幅抖动 |
| `B` | 短时爆发 | 单桶或相邻两桶的尖峰，与前后形成强反差 | 孤峰；前后明显更低 |
| `D` | 衰减/退潮 | 强度从高位逐级走低 | 台阶式下滑 |
| `X` | 数据缺失/不可判 | 该区间为采集后时段或采集快照缺失 | 材料中 `bucket_state=post_snapshot/unknown_fetch` |

**判据锚点是"相对该视频自身"**：不看绝对条数（600 条池的上限本身会截断高活动视频，这正是 C1 选
`got<600` 的原因）。同一条 8 条/分的桶，在全程贴地的视频里是 `H`，在全程 40 条/分的视频里是 `L`。

**最低持续时间**：任何阶段 ≥ 1 个分钟桶（60s）。依据：数据粒度即评估粒度；更短的"阶段"在 60s 序列上
不可定义、不可评估（60s 容差 = 1 桶）。相邻同类段之间允许合并；`B` 类允许多个孤峰合并为一段，
前提是峰间隔 ≤ 2 桶，超过则拆分。

## 4. 特殊情形

| 情形 | 处理 |
|---|---|
| 长时间无弹幕（片头/片尾贴地） | 如实标 `L`；**不**猜测"这里本来该有弹幕" |
| `bucket_state = post_snapshot` 或 `unknown_fetch` | 标 `X`，并在 note 写 `post_snapshot` / `no_fetch`；**禁止当 0** |
| 内部空洞（`n_interior_holes > 0`，被两个非零段夹着的零桶） | 单桶空洞并入相邻段（在 note 记 `hole`）；连续 ≥3 桶空洞拆段并标 `X` |
| 多个峰连片（峰间隔 ≤ 2 桶） | 合并为一段 `B`；峰间隔大则各标各的 |
| 模糊边界（±1 桶内拿不准） | 按"信号变强的第一桶"取 `start_bucket`，`confidence` 填 `low`；**不许**跳过不标 |
| 整片无变化 | 标单段，类别取主导形态（多为 `L` 或 `H`） |
| 曲线材料与实际观感冲突 | **以实际观看为准**，在 note 注明 `curve-mismatch`（沿用 annotation_guides v0 纪律） |

## 5. 标注流程（双人独立）

1. 两位标注者**各自独立**完成 30 支，产出 `ann_A.csv` / `ann_B.csv`；**互不可见对方进度与结果**；
2. 每支视频：先完整观看一遍（正常速度），再回看对照 `curves.csv`（60s 曲线，辅助）；
3. 每段填一行：`bvid, seg_id, start_bucket, end_bucket, category, confidence, note`
   （`confidence ∈ {high, low}`；`note ≤ 10 字`）；
4. 正式标注前，两人各看 2 支**练习视频**（从 pool 里未入选的 255 支中取，不进正式 30 支），
   对齐类别理解后再开始；
5. 标注期间不得讨论彼此的边界判断；对协议本身的疑问可以问，但**回答只能引用协议条文，不得现场造新规则**
   ——遇到协议未覆盖的情形，记入 `disagreements` 清单，由裁决步骤处理。

## 6. 一致性评估（Gate A）

- **边界一致率**（主指标，对应候选门槛 ≥70%）：
  - 匹配算法：对每支视频，把 A 的每个**阶段边界**（每段的 `start_bucket`，以及最后一段的 `end_bucket+1`）
    与 B 的边界集合做**双向贪心最近匹配**；一个 A 边界只配一个 B 边界；`|Δ| ≤ 60s`（=1 桶）记命中；
  - 分母：**人工边界总数**（A 与 B 的边界数之和的较小者所在口径见下）；
  - 一致率 = 命中边界对数 / min(#A 边界, #B 边界)？——**不**。采用双边报告：
    `recall_A→B = 命中 / #A边界`，`precision_A→B = 命中 / #被匹配的B边界 + 未被匹配的B边界`，
    主指标取 **F1**（两个方向的调和均值），并同报 recall 与 precision；
  - 门槛：**F1 ≥ 0.70（60s 容差）**。这是预设候选门槛，不是已达成的结果。
- **类别一致率**：对配对成功的区间计算类别相同比例（Kappa 需要类别分布，阶段段数少时以原始一致率为主报）。
- 必须报告：视频数、阶段段数（A/B 各自）、边界数、F1/recall/precision、逐视频结果、总体结果、
  区间估计（视频级 bootstrap 95%CI，B=2000，种子固定）、主要分歧类型清单。
- **Gate A 未通过（F1 < 0.70）**：如实报告负结果，C1 判负，**不得**进入 Gate B 的正式结论。

## 7. 算法有效性评估（Gate B，仅在 Gate A 通过后）

- 评价参照：**裁决后的人工边界**（见 §8）。
- 边界匹配算法与容差：同 §6（60s = 1 桶）。
- 指标：中位边界误差（秒）、60s 内匹配率、边界 precision / recall / F1、相对基线的增量、
  逐视频分布与失败案例、对缺失/低活动视频的敏感性。
- **预设基线（不得事后增删）**：
  1. 等频分段：把 `[0, n_buckets)` 均分为 k 段（k = 该视频人工段数）；
  2. 单变点基线：在累计计数曲线的最大单变点处切一刀（O(n) 扫描）；
  3. C1 候选方法（另行实现，见 exp49）。
- **预设候选门槛**：中位边界误差 ≤ 15s 且 60s 匹配率 ≥ 60%。
  ⚠️ 与数据粒度的关系：60s 粒度下"中位误差 ≤ 15s"意味着多数边界与人工边界**同桶**。
  这是刻意从严的门槛（沿用 40 号文档的既有口径）；若运行前发现与粒度冲突，只允许在
  **看到任何算法结果之前**调整并记录，运行后不得挑选有利指标。
- **失败重试预算**：Gate B 未通过时，允许**一次**基于失败分析的、预先写明的调整（如换 cost/惩罚）；
  再不过即如实报告负结果。第二次调整 = 协议违规。

## 8. 分歧裁决

- 对每一支视频，列出 A/B 的分歧边界与分歧类别；
- 裁决顺序：先由两人对照曲线各自说明理由 → 能达成一致则改用一致版；不能 → 由**第三人**（未参与标注、
  未看算法输出）裁决；
- 裁决结果写入 `ann_final.csv`，并保留 `ann_A/ann_B` 原始文件（不覆盖）；
- 裁决记录进 `disagreements.csv`：`bvid, type(boundary/category/segment-count), detail, resolution`。
