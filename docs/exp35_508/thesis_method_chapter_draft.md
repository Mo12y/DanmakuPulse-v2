## 3.1 研究任务的定位与边界

本文研究的是**离线、给定观测快照**条件下的播放位置预测：对一条视频的某一时刻 `t`，只用该快照中 `time_offset < t` 的弹幕计数序列，判断 `[t, t+30s)` 内是否出现"相对于决策点近期基线的统计爆发"。

必须与三类相邻任务区分开，否则结论会被过度解释：

1. **不是实时预警。** 日频快照在采集完成的时刻已经包含 `time_offset > t` 的全部弹幕。若把"预测时点"设在观众播放到 `t` 的那一刻，则 `offset < t` 的弹幕当时尚未产生，特征不可得；若把预测时点设在采集时刻，则未来弹幕也已存在，标签已可观测。两个时点无法同时满足"特征可得"与"标签未知"。因此本任务的可检验范围止于"给定快照的离线插值式预测"。
2. **不是热度/排名/留存预测。** 目标量是同一视频内部的局部时间结构，不是视频级的总量指标。
3. **不是"高光/精彩时刻"识别。** 标签只表示"计数相对近期基线显著抬升"，不含任何内容语义判断；本文不主张爆发等于精彩。

## 3.2 数据来源与数据治理

### 3.2.1 数据来源

数据为 B 站热榜视频的弹幕观测快照，按批次采集并落入数据仓库的 ODS 层。本文使用的是 4 个批次（2026-09-02、09-07、09-14、09-17）的 ODS 原始弹幕，共 676,931 行、508 支视频、509 个"视频×批次"快照（其中 1 支视频在两个批次各出现一次）。

**唯一的正式数据层是 ODS 原始弹幕。** DWD 层经过质量筛选与文本维度去重，仅用于独立的敏感性分析；两层的结果不得混合，输出目录物理分离。

### 3.2.2 标识与去重

ODS 表结构中没有名为 `dmid` 的字段，与弹幕唯一标识语义对应的是 `row_id`。判定依据有三条：全部 676,931 行的 `row_id` 均为 19 位数字串；同一条弹幕在不同批次中出现时 `row_id` 相同（否则不会产生 2,433 个"内容相同"的跨批重复）；同一 `row_id` 不跨视频（跨视频组数为 0）。因此正式去重键取 `dmid := row_id`。

去重的作用域需明确区分两个层次：

- **全局唯一性指标**：全表 676,931 行按 `dmid` 去重后为 674,498 个唯一标识，重复 2,433 个 ID / 4,866 行，全部来自同一支视频在两个批次的重复采集。
- **序列构建时的去重规则**：按"视频×批次"快照**内部**去重。原因是两个快照是两次独立观测，全局去重会削掉其中一个快照的 2,433 行，使其桶序列不再对应任何一次真实采集。

同一快照内部的重复 `dmid` 数为 0，因此该规则不改变任何序列的计数，但它把"去重"的语义固定下来，避免后续实现出现两种口径。

### 3.2.3 可追溯性与隔离

- 每个输入文件在清单中登记 `sha256`、字节数与行数；实验前校验一次，实验中只按清单白名单逐文件读取，**不使用目录通配**。
- 数据划分为 D-train（2026-09-02、09-07）、D-dev（09-14、09-17）与 D-conf（冻结之后才开始采集的批次）。三者的视频集合互斥；D-train 与 D-dev 的交集为 0，且两侧集合由两次独立调用分别构造后求交，而不是用"取反"的恒等式。
- 程序层对 D-conf 设置三重拒绝：批次号（`>= 20261027`）、路径模式（`dconf`、`dt=2026(1027+)`）、清单行。任一命中即抛异常并中止，不进入"读一半再判断"的状态。
- 未登记批次一律拒绝，**不默认归入训练集**。

## 3.3 标签定义

### 3.3.1 分桶

固定桶宽 `B = 5 s`，桶数 `K = ceil(duration / B)`，第 `k` 个桶的计数为

```
c[k] = |{ i : floor(time_offset_i / B) = k }| ,   k = 0..K-1
```

采用 `floor` 而非直方图函数：常见直方图实现的最后一个桶是右闭区间，会把 `time_offset == duration` 的点并入末桶，与"全区间左闭右开"的约定不一致。本轮数据中 `time_offset` 缺失、为负、超出时长的行数均为 0；`offset == duration` 且时长为 5 的整数倍的 4 行按"归入最后一桶"处理并计数。

### 3.3.2 相对基线爆发

```
λ_t   = mean(c[t-12 : t])                        # 过去 60 s，12 个桶
thr_t = max(3.0, λ_t + 2·sqrt(λ_t))              # 在 t 处计算一次
y_t   = 1[ max(c[t : t+6]) >= thr_t ]            # 未来 30 s，6 个桶
```

三个设计要点：

1. **阈值只在决策时刻计算一次**，未来 6 个桶只参与比较，不在窗口内滚动重算。因此 `max(...) >= thr_t` 与"任一未来桶超限"在数学上等价。
2. **比较含等号**。`λ_t = 0` 时阈值退化为 3，计数恰为 3 即判正。这一条在实现中被固定为 `float64` 的直接比较，不引入 epsilon，也不做四舍五入。
3. **决策点步长等于预测窗口**（6 桶），窗口互不重叠；合法决策点满足 `t + H <= K`（闭区间上界），最后一个合法点必须保留——早期实现用开区间上界会漏掉每支视频的最后一个点。

### 3.3.3 标签的性质（写进局限）

阈值是**相对**的：它随近期强度 `λ_t` 上升而上升，并在 `λ_t` 很小时退化为常数 3。这意味着"高强度的位置"并不自动意味着"更容易被判为爆发"——在同一视频内部，`λ_t` 较高的时刻反而需要更大的绝对抬升才能触发标签。本文在解释任何"局部强度与标签的关系"时必须把这一机械性质与行为学解释分开，不得把前者当作后者。

## 3.4 特征定义

主模型（M2）使用 6 个特征，全部只依赖 `c[0:t]`：

| 特征 | 定义 | 说明 |
|---|---|---|
| `log1p_lam` | `log1p(mean(c[t-12:t]))` | 局部强度；取对数压缩长尾 |
| `slope` | `log1p(mean(c[t-6:t])) − log1p(mean(c[t-12:t-6]))` | 对数差分趋势；**不使用比值式**，避免分母趋零时产生 1e6~1e9 的伪值 |
| `since` | 距上次"同类爆发"的桶数（见下） | 局部时间结构 |
| `censored` | `since` 是否删失（0/1） | 与 `since` 分列，避免把"从未发生"与"恰好 12 桶前"混成同一个值 |
| `prog` | `t / K` | 播放位置（归一化进度） |
| `log1p_duration` | `log1p(duration)` | 播放前已知的元数据 |

**`since` 的构念。** 若用绝对阈值（如"计数 ≥3"）来标定"上次活跃"，测到的并不是标签所定义的那个事件。本文改为**滚动参照**：对每个历史桶 `k ∈ [max(12, t−12), t)`，用其自身前 60 s 基线计算阈值并判断是否超限，

```
e_k = 1[ c[k] >= max(3, λ_k + 2·sqrt(λ_k)) ] ,  λ_k = mean(c[k-12 : k])
since_t = min{ d ∈ [1,12] : e_{t-d} = 1 }，不存在则 since_t = 12, censored_t = 1
```

如此 `e_k` 与标签使用同一函数形式，`since` 才真正表示"距上次同类爆发的时间"。全部输入 `k <= t−1`，因果合规；标签本身仍用决策点固定基线 `λ_t`，不违反"阈值不在未来窗口滚动"的要求。首个决策点 `t = 12` 没有可观察的更早事件，必然得到 `since = 12, censored = 1`。

**辅助特征 `ent`（仅次要模型 M3）。** 过去 12 个桶的计数分布熵，按**全部 12 个桶**归一：

```
ent = −Σ p_k log p_k / log(12)
```

全零窗口定义为 0，单桶集中为 0，均匀分布为 1。若按"非零桶个数"归一，`[1,1,0,…,0]` 会得到 1.0（最大分散），与直觉相反；按 12 桶归一则得到 0.279。

**特征白名单。** 采用显式白名单，而不是"删掉几个已知泄漏列后把剩余列交给模型"。任何不在白名单的列在建模前立即报错，不静默丢弃。黑名单至少包括：未来 6 个桶的计数、全片弹幕总量、标签及其中间量、任何只在视频结束后才能知道的字段、以及任何 `time_offset >= t` 的统计量。实现中对 100% 的决策点做了逐点因果断言：把 `c[t:]` 整体改写成任意值后，该点的特征向量必须逐位不变。

## 3.5 模型与训练

**分类器：L2 正则化的逻辑回归（`C = 1.0`），特征在训练集上做标准化。** 选择线性模型而非树模型/深度学习，理由是：本任务的特征维度低（6~7 维）、样本以视频为簇、结论需要可解释的系数方向；且预先注册的判据是"增量归因"，需要能逐块消融的模型。实现中不做任何超参数搜索，`C` 为字面常量。

**模型命名与状态**（避免"看名字猜构成"）：

| 名称 | 构成 | 状态 |
|---|---|---|
| M2 | 上述 6 特征 | 唯一主模型 |
| M3 | M2 + `ent` | 次要分析 |
| M1 | `log1p_lam` | 主比较基线（依据早期协议的"局部强度"一级，**待研究者签字确认**） |
| M0 / M4 | 无定义 | 只保留接口，调用即报错，不训练、不报告 |

**训练/校准的数据边界**：模型只在 D-train 上拟合；D-dev 只用于开发期调试；D-conf 不参与任何拟合、调参或阈值选择。

## 3.6 评估协议

### 3.6.1 主指标

主指标是**未见视频上的视频宏平均视频内 AUC**：

1. 对每支合格视频单独计算视频内 ROC-AUC；
2. 对视频 AUC 等权平均（每视频一票），不按点数或时长加权；
3. 不把所有决策窗口混池后计算总体 AUC 作为主指标。

统计单位是视频（`bvid`），同一视频的全部快照与决策点作为一个簇。合格判据为：每视频至少 5 个有效决策点、至少 2 个正例、至少 2 个负例。单类视频（全 0 或全 1）**排除**，不用 0.5 填补——填补会把"从不爆发"错误地记为"无判别力"。

选择视频内口径而非混池口径的理由是混池 AUC 会被跨视频基率差主导：一个在同一视频内恒为常数的变量（例如视频时长），其混池 AUC 可以显著偏离 0.5，而视频内 AUC 必然恰为 0.5。本文把"仅时长"模型作为该性质的自检项：它的视频内 AUC 必须精确等于 0.5000，偏离即说明实现有误。

### 3.6.2 不确定性与配对比较

主比较为 `ΔAUC = AUC_macro(M2) − AUC_macro(M1)`，用**配对视频级 Bootstrap** 构造 95% 置信区间：每次重采样以 `bvid` 为单位抽取整支视频，两个模型使用同一批被抽中的视频；重采样次数与随机种子写入报告。若某次重采样的可用视频数低于半数，则该次样本视为退化并丢弃，同时记录丢弃次数。

### 3.6.3 校准

概率展示需要独立于判别力的校准门。唯一实现方式是**按 `bvid` 分组的 5 折交叉拟合**：

1. 把 D-train 的视频随机分到 5 折（同一视频的全部点在同一折）；
2. 对每一折，用其余 4 折拟合基础模型，对本折打分，得到折外分数；
3. 用全部折外分数与标签拟合 Platt 校准器（对 `logit(p)` 的一维逻辑回归）；
4. 正式使用时，在全 D-train 上重拟合基础模型并套用该校准器。

关键区别：**用于拟合校准器的是折外分数，不是基础模型对其训练视频产生的训练内分数**。后者会让校准器高估置信度。实现中逐折断言"训练侧与测试侧的视频交集为 0"。

校准指标报告校准斜率、校准截距、10 分位可靠性曲线、Brier 与 Brier skill；不使用 ECE（对分箱敏感）。

### 3.6.4 负对照

评估管道必须能"失败"。协议规定三类负对照：标签置乱、时间窗前移、仅时长模型。本轮实现与实测发现其中两项**不具判别力**，需修订后重新预注册：

- **标签置乱**必须作用在**评估侧**（真标签拟合 → 对置乱标签评估）。若在拟合侧置乱（置乱标签拟合 → 对真标签评估），"视频内置换"并不构成零假设：它保留了每支视频的均值特征与均值标签之间的跨视频关系，模型仍能学到真实结构，因而给出系统性偏离 0.5 的结果。
- **时间窗前移**对本文的 60 s 聚合特征几乎不改变输入，因而不构成有效对照；应改为"打乱桶序"或"用相邻视频的特征替代"。
- **仅时长模型**是唯一稳定有效的对照：视频内 AUC 必须恰为 0.5。

## 3.7 系统实现框架

实现遵循"**协议—代码—清单同仓**"的组织方式，使冻结时三者落在同一个提交里：

| 组件 | 位置 | 职责 |
|---|---|---|
| 正式实现 | `jobs/m2_l6_burst_risk.py` | 序列构建、标签、特征、白名单校验、切分、模型、主指标、配对 Bootstrap、交叉拟合校准、负对照、清单核验、D-train-only 分析 |
| 单元测试 | `tests/test_burst_{label,features,split,calibration,eval,isolation}.py` | 91 项，覆盖标签语义、特征定义、因果约束、切分隔离、校准不变量、评估口径、数据隔离 |
| 协议与清单 | `docs/exp35_508/` | 协议候选版本、数据清单、哈希、ID 列表、审计报告、分析产物 |
| 运行产物 | `data-out/m2_l6/ods/`（与 `dwd_sensitivity/` 分离） | 点表、清单校验结果、审计 JSON、功效与门槛模拟结果 |

设计上的三个约束值得在论文中说明：

1. **纯函数化的标签与特征**：标签与特征函数只接受"单条序列 + 决策点"，不接触文件系统与全局状态，因此可以完全用合成序列做单元测试（含边界、性质测试），而不依赖真实数据。
2. **失败即中止**：特征列越界、批次未登记、路径命中 D-conf、训练集单一类别、重采样有效次数不足等情况一律抛异常，不返回"部分结果"。
3. **产物带自证信息**：每个阶段输出 JSON，记录协议版本、随机种子、重复次数、输入文件的 `sha256`、样本量与丢弃计数，使结果可被独立复算。
